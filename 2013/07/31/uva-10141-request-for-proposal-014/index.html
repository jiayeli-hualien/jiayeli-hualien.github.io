10141 - Request for Proposal

初版驗證狀態：尚未完成目前程式與原始 Accepted 紀錄的比對；後續確認後會補上驗證資訊。

題目要做什麼

每筆 RFP 有多項需求和多份提案。每份提案會列出符合的需求數與價格；要選出符合需求最多的提案。如果符合數相同，選價格較低者；若符合數和價格都相同，保留輸入順序較早的提案。每筆 RFP 輸出編號與提案名稱，輸出之間空一行。

解法

同一筆 RFP 的需求總數固定，因此符合率最高等同於符合需求數最多。逐份讀取提案後，只需用「符合數較多、或符合數相同但價格較低」更新目前最佳提案。比較時不更新完全平手的提案，就會保留先輸入者。

需求名稱和提案列出的需求名稱不必保存，讀入後即可丟棄；題目只要求用符合數和價格選出提案。因需求名稱與提案名稱可能包含空白，整行使用 getline 讀取。讀完每個提案的價格和符合數後，再跳過接下來的符合需求名稱。

處理每筆資料的時間與需求行數、提案數和提案列出的符合需求行數成正比；額外只保留目前最佳提案和一行輸入內容。

範例

官方範例的第一筆 RFP 有六項需求。Chevrolet 和 Hyundai 各符合三項，Lada 符合一項，Cadillac 符合四項，因此選 Cadillac；價格不會推翻符合數較多的結果。第二筆 RFP 只有一項需求，Starbucks 符合該需求，輸出其名稱。
