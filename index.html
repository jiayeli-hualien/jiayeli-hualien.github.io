鏈結串列基本知識

鏈結串列，英文 linked list，是一種資料結構， list 中有多個節點，每個節點當中至少會有兩個成員變數:

  • data/key: 儲存資料的空間，一般會用 int 當作範例，實務上可能會遇到自訂的 struct / pointer / smart pointer ， 或是更瘋狂的 Linux kernel 當中需要利用 macro container_of() 來算回 data 的 address
  • next: 指出下一個節點的 address

UVa

12247 - Jollo

題目要求

一副牌有 52 張，以 1 到 52 表示。遊戲共三局，每局兩人各出一張牌，牌面較大者贏該局；先贏兩局者贏得整場。公主已拿到三張牌，王子目前有兩張。發牌者看過這五張牌後，要從其餘牌中挑一張 Z 加入王子的手牌，找出能保證王子獲勝的最小 Z；如果沒有這種牌就輸出 -1。每筆輸入給出五張互不相同的牌：A B C 是公主的牌，X Y 是王子的牌；五個數字都是 0 時代表輸入結束。

「保證獲勝」表示不論三局中雙方怎麼安排出牌，王子都至少能贏兩局。因此，固定一張候選牌 Z 後，要檢查公主最多可能贏幾局。

解法

要找出最小的未發牌 Z，讓王子不論出牌順序如何都能贏得三局兩勝。固定候選 Z 後，把三局視為三組牌的配對，計算公主最多能贏幾局。若最多一勝，王子至少贏兩局；若公主可能贏兩局，這張 Z 就不安全。

固定 Z，計算公主最多能贏幾局

把公主的三張牌和王子的三張牌分別由小到大排序，從兩邊最小的牌開始配對。

  • 若目前最小的公主牌不大於王子最小的牌，它連王子最小的牌都贏不了，也就贏不了其他王子牌，可以略過。
  • 若公主牌較大，就把這兩張牌配成公主的一勝，再各自看下一張牌。

這樣會得到公主能拿到的最大勝場數。若目前最小的公主牌能贏過最小的王子牌，總能找到一個最佳配對包含這一對：若目前的公主牌原本配給較大的王子牌，改配給最小王子牌仍能獲勝；若最小王子牌配給另一張公主牌，則可交換兩組配對，兩張公主仍都能獲勝。若其中一張牌原本未配對，直接改配也不會減少總勝場。

由小到大測試 Z

牌面是 1 到 52。略過已發給公主或王子的五張牌，依序測試其他牌。對每張候選 Z 計算公主最多能贏幾局；第一張使公主最多只能贏一局的牌，就是答案。若全部試完仍找不到，就輸出 -1。

例如輸入 10 20 30 24 26 時，未發的最小牌是 21。三張牌排序後，公主是 10, 20, 30，王子是 21, 24, 26。10 和 20 都無法贏過王子最小的牌 21；30 最多只能贏一局，因此答案是 21。

每組測資最多檢查 52 張候選牌，每次只排序三張牌，時間為 O(52)，額外空間為 O(1)。

10309 - Turn the Lights Off

題目要求

每筆測資先給一個名稱，接著給 10×10 棋盤：O 表示燈亮，# 表示燈熄；名稱為 end 時輸入結束。按下一格的開關會反轉該格以及上下左右相鄰格的燈，超出棋盤的方向不作用。題目要找出讓整個棋盤熄燈所需的最少按鍵次數。若無法全部熄燈，或最少次數超過 100，就輸出 -1；每筆輸出包含測資名稱和答案。

下圖用 3×3 小棋盤示範按下中央開關，如何一次熄掉中央與上下左右的燈；對角線上的燈不變。O 代表亮燈，# 代表熄燈；黃底表示亮燈，灰底表示熄燈。

解法

解法分成兩步：枚舉第一列的按法，再由上往下推導其餘各列。每個候選方案推完十列後，檢查棋盤是否全暗，從可行方案中取最少按鍵數；沒有可行方案或最少次數超過 100，就輸出 -1。

為什麼只窮舉第一列

同一個開關按兩次會抵消，因此只需考慮每個位置按或不按一次。

不能把「看到亮燈就按」直接套用在第一列，因為第一列的燈還會受下方開關影響；第一列沒有前一列的狀態可用來決定按法，因此要枚舉十個開關的 2^10 = 1024 種組合，而不是枚舉全盤 100 個開關的 2^100 種組合。

固定第一列後，從第二列開始逐列處理。若上一列某格仍亮著，只有正下方的開關能再影響那格，所以必須按；若已熄滅，就不按。每列的按法因此都由上一列唯一決定，不必再枚舉。

處理完第十列後，所有前九列都已清除，還要檢查最後一列是否也全暗。若全暗，這組按法可行；在 1024 種第一列按法中取按鍵數最少者，即為答案。

每個候選第一列只需模擬 100 個位置，因此時間複雜度為 O(2^10 × 100)，額外空間為 O(100)。

11336 D:DRAM

題目 UVa 11336 - D:DRAM 要判斷新地圖是否為舊地圖的「更詳細版本」。判斷必須同時符合兩個條件：

  • 新地圖包含舊地圖的所有地點。
  • 舊地圖每一條道路 A-B，都能在新地圖中找到一條從 A 到 B 的路線，而且中途只能經過新地圖有、舊地圖沒有的地點。直接保留 A-B 也符合條件，因為路線沒有中途地點。

假設舊地圖有道路 A-B，下圖比較兩種新地圖中的替代路線。A、B 是舊地點；藍色節點代表舊地點，綠色節點代表新地圖新增的地點。A-X-B 符合條件；A-C-X-B 不符合，因為中途經過的 C 已存在於舊地圖。

因此，先確認舊地點都出現在新地圖，再對每一條舊道路做 BFS。搜尋時只穿過新地點，抵達舊道路的另一端就算找到替代路線。

路線為什麼只能經過新地點？

假設舊地圖有道路 A-B。新地圖可以用 A-X-B 取代它，只要 X 是新增加的地點。但若路線是 A-C-X-B，而 C 已經存在於舊地圖，這條路線就不符合題意：舊道路的中途地點必須全部是新地點。

BFS 從舊道路的一端出發，只把新地點加入佇列；遇到另一端時立即成功。這樣找到的路徑端點是原道路的兩個地點，所有中途地點則必定是新地點。

演算法

  1. 讀取兩張地圖，將道路視為無向邊，並以鄰接串列儲存。
  2. 檢查舊地圖的每個地點是否都在新地圖中；同時標記新地圖中的舊地點。
  3. 對舊地圖的每一條道路 (u, v)，在新地圖中從 u 執行 BFS。搜尋只穿過新地點，若能到達 v，代表這條舊道路有合法替代路線。
  4. 所有舊道路都有替代路線時，輸出 YES；只要有一個條件不成立，就輸出 NO。

若舊地圖有 M 條道路，新地圖有 V 個地點與 E 條道路，最壞時間複雜度為 O(M(V + E))，空間複雜度為 O(V + E)。

10114 - Loansome Car Buyer

題目要做什麼

已知頭期款、貸款金額、貸款期數和各月份的折舊率，找出經過幾個完整月後，車價首次高於剩餘貸款。輸出這個月數；答案為 1 時用單數 month，其餘用 months。

每個月更新車價與貸款

車子剛離開車行時，原始價值是「頭期款 + 貸款金額」。題目把這個尚未經過一個月的時點記為第 0 月：此時立即套用第 0 月的折舊率，但還沒有繳分期款。第 1 月則是經過第一個月後；之後每個月底套用當月折舊率，再繳一次分期款。貸款沒有利息，因此每期付款是 貸款金額 / 貸款期數。程式沿用題目定義的月份編號，不是任意從 0 開始編號。

折舊率是從當下車價扣除的比例。例如折舊率為 10%，新車價就是「原車價 × (1 - 0.10)」，程式以 carValue *= 1.0 - rate 更新。

題目保證第 0 月有折舊紀錄；後續紀錄按月份遞增。若某月沒有新紀錄，就沿用最近一筆折舊率。從第 0 月開始逐月更新兩個數值，第一次出現「尚欠金額 < 車子價值」時，當月就是答案。題目要求嚴格小於；兩者相等時還不能停。

車價和欠款可能低於 1 美元，計算時不可逐月四捨五入；程式保留 double 的小數值直接比較。

設貸款期數為 n、折舊紀錄數為 m。程式逐月模擬 n + 1 個時點，並只向前掃描折舊紀錄，因此時間複雜度為 O(n + m)，額外空間複雜度為 O(m)。

範例

第一筆範例的車子初始價值為 15,500，第 0 月立即折舊 10%，車價變成 13,950，但仍欠 15,000。第 1、2 月各折舊 3%，第 3、4 月各折舊 0.2%；每月底同時繳 500 元。第 4 月月底車價約為 13,073.10528，尚欠 13,000，第一次低於車價，所以輸出 4 months。

下圖中的第 0 月是立即折舊後、繳款前的數值；第 1 至 4 月則是每月底更新後的數值。第 4 月月底車價首次高於欠款。縱軸有截斷，方便看出兩者的差距。

11507 - Bender B. Rodríguez Problem

題目要求

題目中的金屬線（metal wire）可以想像成一條可彎折的鐵絲。它的長度為 L，固定端在原點，自由端一開始位於 (L, 0, 0)，因此整條線沿 +x 方向。Bender 從自由端往固定端依序處理 L - 1 個彎折點：No 表示不彎，其他指令表示在該點轉彎 90 度。題目要輸出全部彎折完成後，末段線的方向。

解法概念：追蹤末段方向

只要追蹤自由端末段的方向，不必計算自由端最後的位置。用方向向量 d = (x, y, z) 表示目前末段的方向，初始朝 +x，所以 d = (1, 0, 0)。No 不改變方向；其他指令則根據目前方向更新向量。

以 L = 3、指令依序為 +y、-y 為例，圖中逐步追蹤末段方向；處理完兩個指令後，方向仍是 +x。

題目只要求末段方向，因此圖只呈現計算時追蹤的向量狀態，不畫整條線的位置座標。箭頭表示依輸入順序處理指令，也就是從自由端往固定端。

圖中示範了方向狀態如何依序更新；接下來把四種彎折指令整理成一般的向量規則。

彎折指令的向量規則

假設彎折前的方向向量是 d = (x, y, z)，彎折後是 d' = (x', y', z')。各指令依下列規則更新分量；右側的 x、y、z 都是彎折前的值：

指令 彎折後的向量 d'
+y (-y, x, z)
-y (y, -x, z)
+z (-z, y, x)
-z (z, y, -x)

以 +y 為例，彎折前朝 +x 的分量會轉向 +y，朝 +y 的分量會轉向 -x，而 z 分量不變。因此彎折前的 d = (x, y, z) 會變成 d' = (-y, x, z)，也就是 x' = -y、y' = x、z' = z。公式右側都是彎折前的分量。這些更新在數學上等價於 90 度旋轉，但程式不必建立旋轉矩陣，也不需要浮點數。

因為初始方向是座標軸方向，而每次彎折只會交換分量並改變正負號，方向始終是以下六種之一：+x、-x、+y、-y、+z、-z。換句話說，三個分量中只有一個是 1 或 -1，另外兩個是 0。因此可以把這六個方向編號，預先整理每種方向遇到各指令後會變成什麼方向。

下表就是把上面的向量規則列舉成六種方向的轉換表。列是彎折前的方向，欄是本次指令，交叉處是彎折後的方向。例如目前朝 +z 時，向量是 (0, 0, 1)；套用 +y 規則仍是 (0, 0, 1)，所以方向不變。

目前方向 +y -y +z -z
+x +y -y +z -z
-x -y +y -z +z
+y -x +x +y +y
-y +x -x -y -y
+z +z +z -x +x
-z -z -z +x -x

程式如何套用轉移表

程式不必真的存三個分量，而是以 0 到 5 分別代表 +x、-x、+y、-y、+z、-z。nextDirection 將向量規則整理成查表：列索引是目前方向，欄索引是 +y、-y、+z、-z。每讀到一個非 No 指令，就查表更新方向；全部處理完後，從名稱表輸出結果。

每筆測資讀取 L - 1 個指令，時間複雜度為 O(L)，除固定大小的轉移表外只使用常數額外空間。

驗證

  • UVa 官方範例通過。
  • uDebug 第二組公開測資（24 組彎折組合）通過；第一組 100 筆的轉移結果也與 Accepted Output 相符。
  • 本機以 C++11 編譯後，與獨立的整數向量旋轉參考程式比對 19,531 組案例：涵蓋 6 次彎折以內的所有指令序列，另含 L = 100000 的長案例，結果一致。

10415 - Eb Alto Saxophone Player

UVa 10415 給一段由 14 種音符組成的樂曲，要求分別計算十根手指按下按鍵的次數。對每個音符，某根手指只有在「這個音符需要它、前一個音符不需要它」時才算按下一次；每首樂曲的第一個音符則視為前一刻沒有手指按著。輸出十個計數，順序是手指 1 到 10。

用前後音符的按鍵狀態計數

先把每個音符表示成十根手指的按鍵狀態。以下表格中的數字是手指編號：

音符 需要按住的手指
c 2、3、4、7、8、9、10
d 2、3、4、7、8、9
e 2、3、4、7、8
f 2、3、4、7
g 2、3、4
a 2、3
b 2
C 3
D 1、2、3、4、7、8、9
E 1、2、3、4、7、8
F 1、2、3、4、7
G 1、2、3、4
A 1、2、3
B 1、2

例如樂曲 abC：第一個音符 a 需要手指 2、3，因此兩者各計一次。切換到 b 時仍需要手指 2，沒有新按下；再切換到 C 時需要手指 3，而前一個音符 b 沒有用到手指 3，所以手指 3 再計一次。結果是手指 2 按 1 次、手指 3 按 2 次，其餘為 0。

程式用長度 10 的布林陣列保存前一個音符與目前音符的狀態。每讀到一個音符，就依照對照表建立目前狀態；若某個位置目前為 true、前一狀態為 false，便增加該手指的計數。處理完後，將目前狀態存為前一狀態。

程式用 notes 與 fingering 兩組同索引資料保存對照：notes 中某個音符的位置，就是它在 fingering 中的按鍵字串。按鍵字串以陣列索引 0 到 9 表示手指 1 到 10，所以字元 '0' 代表手指 1；例如音符 c 的字串是 "1236789"，代表手指 2、3、4、7、8、9、10。

每首曲子都重新把計數和前一狀態設為 0。題目允許空曲子，所以每個測資必須用 getline 讀取一整行；空行會輸出十個 0。讀入測資數後，先用一次 getline 消耗該行剩餘的換行字元，再逐行讀取曲子。

C++11 程式

每個音符查出所需手指後，檢查十個位置一次；一首最多 200 個音符，因此每首曲子的時間為 O(10L)，其中 L ≤ 200。額外狀態只保存十根手指，空間為 O(10)。

驗證

整理版以 MSYS2 UCRT64 g++、-std=c++11 -Wall -Wextra -pedantic 編譯，官方範例與 uDebug 提供的 12 筆資料全部相符；另測試空曲子、同音符連續出現、以及不同測資之間的狀態重設。UVa 題目敘述 · uDebug 測資

本篇程式以 C++11 提交 UVa 10415，結果為 Accepted。

10878 - Decode the Tape

UVa 10878 要把紙帶上的孔洞還原成文字。每列代表一個字元；程式從每列的 8 個資料位元重建字元，並在讀到第二條 ___________ 時停止。

每列轉成一個字元

每列左右兩端的 | 是紙帶邊界，中間的 . 用來標示中心位置。略過邊界和點號後，剩下的位置由左至右代表位元 7 到位元 0。讀到 o 就把該位設為 1，讀到空白則設為 0。

程式以從 0 開始的字串索引讀取固定欄位：左右邊界在 row[0] 和 row[10]，中央的 . 在 row[6]；資料位元位於 row[1] 到 row[5]，以及 row[7] 到 row[9]。因此迴圈檢查索引 1 到 9，並略過索引 6。

題目沒有明說這 8 個位元要用哪種字元編碼。可以從範例推知：官方範例第一列讀成 01000001₂，換算為十進位是 65；依 ASCII 對應為 A，正好是範例訊息的第一個字元。因此本文按 ASCII 解碼，但要注意這項規則是從範例推得，題目敘述沒有明文交代。

程式由左至右逐位累積：先把目前值左移一位，再放入新位元。以 01000001 為例，讀完前兩位後目前值是 1；再讀入 0 時，先左移得到 2，再加入 0，後續位元依此類推，最後得到 65。

輸入的第一條 ___________ 是紙帶起點；之後每讀到一列就輸出一個字元，直到讀到下一條分隔線。這樣每列都會解碼一次，並保留訊息中的空格、標點和換行字元。

C++11 程式

每列處理固定 8 個資料位元，因此共有 N 列時，時間為 O(N)；程式只保存目前一列和一個位元組，額外空間為 O(1)。

驗證

整理版以 MSYS2 UCRT64 g++、-std=c++11 -Wall -Wextra -pedantic 編譯；以程式產生 0 到 127 的 ASCII 紙帶列，解碼結果逐位元組相符。另用 uDebug 提供的完整紙帶資料解碼，結果與 Accepted Output 相符（將文字欄位正規化的換行形式統一後）。UVa 題目敘述 · uDebug 測資

本篇程式以 C++11 提交 UVa 10878，結果為 Accepted。

10125 - Sumsets

每筆輸入是一組互不相同的整數：先給元素數量 n（1 ≤ n ≤ 1000），再給 n 個整數；輸入以 n = 0 結束。從集合中選出四個不同的數值 a, b, c, d，使 a + b + c = d。如果有多組答案，輸出最大的 d；若沒有答案，輸出 no solution。

解法摘要

將 a + b + c = d 改寫成 a + b = d - c。由大到小嘗試 d，對每個 c 查詢是否有兩個數的和等於 d - c。為了加速這些查詢，先建立所有兩數和並排序，再用 binary search（二分搜尋）找目標值；每筆和都保留組成數對的索引，以排除重複使用元素。最壞時間複雜度為 O(n² log n)，額外空間複雜度為 O(n²)。

從 2SUM、3SUM 到 4SUM

2SUM：給定一組數和目標和 t，找兩個不同的數 a、b，使 a + b = t。數列排序後，可以用雙指標在 O(n) 時間回答一次查詢。

3SUM：給定目標和 t，找三個數使總和等於 t。固定其中一個數 a，剩下的問題就是目標為 t - a 的 2SUM；排序後逐一固定 a，總時間為 O(n²)。

4SUM：給定目標和 t，找四個數使總和等於 t。把四個數分成兩對，可改寫成 x₁ + x₂ = t - (x₃ + x₄)。預先建立所有數對的和，再查詢互補的和，就能把直接枚舉四個數的 O(n⁴) 降為 O(n² log n)，代價是使用 O(n²) 空間。

本題和 4SUM 一樣要選四個互異的數，但右側的 d 也必須來自集合，且題目要求最大的 d。因此可以把每個候選 d 看成一次目標值為 d 的 3SUM；更進一步固定 d 和 c，就得到目標值為 d - c 的 2SUM。這個轉換讓我們能把所有 2SUM 查詢共用同一張兩數和表。

以官方範例 2, 3, 5, 7, 12 為例，先嘗試最大的 d = 12。固定 c = 2 後，目標值是 12 - 2 = 10；數對 (3, 7) 的和為 10，而且四個數互異，因此答案是 12。

如何選擇查詢方法

d、c 都要從集合中選，最多會有 n(n - 1) 組候選，也就是最多 O(n²) 次 2SUM 查詢。可以按下列方式選擇每次查詢的演算法：

做法 單次 2SUM 查詢 最壞總時間 額外空間 取捨
每次掃描全部數對 O(n²) O(n⁴) O(1) 寫法直接，但查詢很多時較慢
排序原數列後用雙指標（跳過 c、d） O(n) O(n³) O(1) 省空間，需為每組 (d, c) 重做查詢
預先建立並排序兩數和，再用二分搜尋 O(log n) O(n² log n) O(n²) 多用空間，換取較低的最壞時間；本解法採用此方法

若優先省記憶體，可以選排序加雙指標，接受 O(n³) 的最壞時間。這題的 n 最大為 1000，兩數和表最多有 499,500 筆；因此本解法使用 O(n²) 空間預存結果，將最壞時間降為 O(n² log n)。而題目只要求最大的 d，所以由大到小測試 d，一找到答案即可停止；若高 d 很快找到，實際查詢會更少，但無解時的最壞複雜度不變。

如何確保四個數互異

兩數和表找到總和符合的數對後，還要確認它沒有重用 c 或 d。否則雖然和正確，仍不符合四個數互異的要求。

題目保證輸入的數值互不相同。固定目標和 t = d - c 後，若數對包含 c，另一個數只能是 t - c = d - 2c，所以最多只有一組數對會包含 c；若數對包含 d，另一個數只能是 t - d = -c，所以最多只有一組會包含 d。因此最多兩組數對會因為重用 c 或 d 而無效。若 (c, d) 本身也剛好是目標和為 t 的數對（例如 c = 0），它會同時落在這兩類，但仍只算一組無效數對。

所以，如果同總和至少有三組數對，檢查其中前三組就一定能找到有效數對；如果只有一組或兩組，則要逐組檢查索引，確認是否有一組避開 c、d。

回到集合 { -2, -1, 0, 1, 2, 3, 4, 5 } 的例子，固定 d = 5、c = 2，程式中的查詢目標 target（以下記作 t）是 d - c = 3。兩數和表中，總和等於 t 的數對如下：

數對 檢查結果 原因
(-2, 5) 排除 重用了 d = 5
(-1, 4) 可用 沒有重用 c 或 d
(0, 3) 可用 沒有重用 c 或 d
(1, 2) 排除 重用了 c = 2

程式用 lower_bound 找到第一筆總和等於 t 的紀錄，接著最多檢查三筆同總和的數對；如果數對索引等於 c 或 d 就跳過，否則表示找到答案。表格中的數對順序可能不同，但最多只有兩筆會被排除，所以前三筆中一定有可用的數對。程式函式的參數名稱 target 就是這裡的 t。

複雜度

令兩數和表的大小為 M = n(n - 1)/2。建立表需要 O(n²) 時間，排序需要 O(M log M) = O(n² log n)；最多查詢 O(n²) 次，每次二分搜尋為 O(log M) = O(log n)。因此整體時間複雜度是 O(n² log n)，額外空間複雜度是 O(n²)。原數列排序的 O(n log n) 比表的排序成本低階，不影響總複雜度。

C++11 程式

驗證

整理版以 MSYS2 UCRT64 g++、-std=c++11 -Wall -Wextra -pedantic -O2 編譯。官方範例、邊界案例、200 組隨機小資料（與暴力解比對）及 n = 1000 無解案例均通過。uDebug 的 6 組輸入中，5 組已直接用編譯後執行檔比對；第 4 組有 50 筆資料，在頁面內逐筆計算後與 50 行 Accepted Output 全數相符，但完整輸入尚未直接餵給本機執行檔。
