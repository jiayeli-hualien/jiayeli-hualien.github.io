10783 - Odd Sum

UVa 10783 要求計算閉區間 [a, b] 中所有奇數的總和。輸入先給測資數 T，接著每筆提供 a、b（0 ≤ a ≤ b ≤ 100）；每筆輸出 Case i: sum。題目敘述

用前綴和計算區間總和

定義 oddPrefix[i] 為小於 i 的奇數總和。以 [3, 9] 為例，oddPrefix[10] 是 1 + 3 + 5 + 7 + 9 = 25，oddPrefix[3] 是 1，相減後得到區間內的總和 24。

所以 [a, b] 的答案是 oddPrefix[b + 1] - oddPrefix[a]。用 b + 1 納入右端點；這個寫法也能直接處理 a = 0，不必存取 a - 1。

前綴和只需從 0 到 100 建立一次。每格先複製前一格的總和，遇到奇數再加上它；每筆測資就能用一次相減在常數時間內回答。

10008 - What's Cryptanalysis

UVa 10008 要統計一段文字中，每個英文字母出現的次數。輸入第一行是正整數 n，接著有 n 行文字，也可能包含空白行。大小寫視為同一個字母，空格、標點和數字都忽略。輸出每行列出一個大寫字母、空格及出現次數；只列出至少出現一次的字母，依次數由多到少排列，次數相同時按字母順序排列。題目敘述

統計 26 個字母再排序

例如自訂文字 aB! a? c 中，A 出現 2 次，B 和 C 各出現 1 次，因此輸出順序是 A 2、B 1、C 1。

固定使用 26 個計數器記錄 A 到 Z 的出現次數。讀取每一整行，逐字檢查：大寫字母用 ch - 'A' 找到位置，小寫字母用 ch - 'a' 找到相同位置，其他字元不計數。

統計完成後，只把出現過的字母放入清單，再依「次數遞減、字母遞增」排序並輸出。若共有 L 個輸入字元，時間複雜度為 O(L + 26 log 26)；計數器和排序清單最多各存 26 個項目。

575 - Skew Binary

UVa 575 要把 skew binary 數字轉成十進位。從右邊數第 k 位的權重是 2^(k + 1) - 1（最右位的 k = 0）。每一位的數字可以是 0 或 1，最右側的非零位也可能是 2。輸入每行一個數字，0 表示結束；每個數字的十進位值不超過 2^31 - 1。題目敘述

由右向左累加位值

各位的權重依序是 1, 3, 7, 15, ...，每一項都等於前一項乘 2 再加 1。因此從最右位開始，逐位乘上目前權重並加進答案，再更新權重即可。

例如 10120 的計算是 1 × 31 + 0 × 15 + 1 × 7 + 2 × 3 + 0 × 1 = 44。程式以字串讀取輸入，並以 0 作為輸入終止標記。

題目保證轉換後的答案不超過 2^31 - 1，因此答案與實際用到的權重都放得進 32 位元的 int。不過，目前迴圈在處理完最高位後，仍會執行一次 placeValue = placeValue * 2 + 1；對最大合法值而言，這次更新會得到 2^32 - 1，超過 32 位元 int 的上限。雖然後面不再使用這個權重，溢位仍須避免。因此程式使用 uint64_t 保存權重和答案，省去最後一次更新的特殊判斷，讓寫法保持簡單。

每個輸入位數只處理一次，時間複雜度為 O(D)，其中 D 是位數；額外空間用來保存目前的輸入字串。

579 - ClockHands

UVa 579 給定時間 H:M，要輸出時針和分針之間較小的角度，四捨五入至小數點後三位。時間以 0:00 結束；H 為 1 到 12，M 為 00 到 59。題目敘述

先求兩根指針的位置

指針時鐘的長針是分針，一圈代表 60 分鐘；短針是時針，一圈代表 12 小時。時針會隨時間連續移動，所以 8:10 的時針已略過 8，不會停在 8 上。

上圖為自行繪製的指針位置示意。以下角度都從 12 點方向開始，順時針計算。

一圈是 360°，兩根指針走完一圈所需的時間不同，因此轉動速度也不同：

  • 時針每小時：12 小時走完一圈，所以每小時轉 360° ÷ 12 = 30°。
  • 時針每分鐘：一小時有 60 分鐘，所以每分鐘轉 30° ÷ 60 = 0.5°。
  • 分針每分鐘：60 分鐘走完一圈，所以每分鐘轉 360° ÷ 60 = 6°。

因此，時間 H:M 的時針角度是 30H + 0.5M，分針角度是 6M。時針公式中的 0.5M，就是這一小時內經過 M 分鐘所前進的角度。

兩角相減並取絕對值，得到一個 0° 到 360° 的角度差 d。兩根指針之間較小的角度是 min(d, 360° - d)。例如 8:10 時，時針在 245°，分針在 60°，角度差為 185°，因此答案是 175°。

424 - Integer Inquiry

用大整數加法求總和

輸入多個非負整數，最後一行的 0 表示輸入結束，請輸出所有數字的總和。題目最多有 100 個數，每個數最多 100 位，連 long long 也放不下。

解法是用陣列分開保存各位數，再像直式加法一樣相加與進位。 先用字串讀入完整數字，就不必把整個數值塞進單一整數變數。本篇先用「陣列一格存一位」說明原理，程式再採用「一格存四位」減少需要處理的格數。

就像直式加法

例如 999 + 2，從個位開始相加，滿 10 就向左進位：

  999
+   2
-----
 1001

個位的 9 + 2 = 11，保存 1、進位 1；十位與百位都因為接到進位而得到 10，各保存 0、繼續進位，最後得到 1001。大整數加法就是把這個過程寫成程式。

先從陣列一格存一位開始

將 999 存成 [9, 9, 9, 0, …]，2 存成 [2, 0, 0, 0, …]。索引 0 保存個位，索引 1 保存十位，依此類推。這樣迴圈從索引 0 往後走，就能按照低位到高位的順序處理。

每格計算 total = 原有數字 + 新數字 + carry，其中 carry 是前一格傳來的進位：

這裡的除法是整數除法。例如 11 % 10 = 1、11 / 10 = 1，正好對應「保存 1、進位 1」。算完 999 + 2，陣列會是 [1, 0, 0, 1, 0, …]；輸出時由高位往低位讀，就得到 1001。

程式為什麼一格存四位？

一格一位已經能解這題。一格四位則把相鄰的四個十進位數字合成一段，讓需要處理的格數約縮成四分之一；加法與進位的原理相同，只是由滿 10 進位，改成滿 10000 進位。

例如 123456789 從右側每四位切一段，得到 1、2345、6789，陣列反向存成 [6789, 2345, 1, 0, …]，讓索引 0 仍代表最低段。每段的值介於 0 到 9999。

對應到程式，BASE = 10000，每段計算：

以 99999999 + 2 為例，每四位一組的直式加法如下：

   9999 9999
+         2
-----------
1  0000 0001

每組滿 10000 就向左進位，結果是 100000001，陣列存成 [1, 0, 1, 0, …]。程式每次都先合併低位並向高位進位，已處理的段就會保持在 0 到 9999 之間；讀完所有輸入後，陣列保存的就是完整總和。

加法安全，乘法也安全嗎？

本題一次把一個新數字加進總和，每段相加連同進位，最大為 9999 + 9999 + 1 = 19999，使用 32 位元 int 足夠。

若改做乘法，就要重新估算中間值，不能直接沿用加法的安全範圍。 單次兩段相乘最多為 9999 × 9999 = 99980001，仍放得進 32 位元 int；但如果先把多個乘積累加到同一格、最後才進位，就可能溢位。例如累加 50 個最大乘積會得到 4999000050，已超過 2147483647。

因此，寫乘法時要連同累加項數與進位估算上限，再決定分段大小、中間值型別和進位時機。若需要 long long，也要讓乘法在該型別下進行，例如 1LL * a[i] * b[j]，而不是等乘法算完才轉型。本題只有加法，目前的四位分段與 int 已足夠。

輸出與容量

最高的非零段直接輸出，其餘較低的段都固定補成四位，才能保留每段的位置。例如 [1, 1] 要由高到低印成 1 接上 0001，得到 10001，不能直接接成 11。上面的連續進位例子則印出 1、0000、0001，接起來才是 100000001。

若總和為 0，仍保留並輸出索引 0 的段，避免往陣列範圍外尋找非零段。輸入即使帶有前導零，輸出也會自然省略多餘的零。

程式使用 50 段的容量，可保存 200 位十進位數字。題目最多將 100 個 100 位數相加，總和最多 102 位，因此容量足夠。

競賽時也可以用語言提供的大整數

若競賽允許使用 Python，這題可以直接把輸入字串轉成 int 再累加，不必自行分段與處理進位。Python 的 int 支援任意精度整數，可以保存本題的 100 位數與總和。

Java 的標準函式庫則提供 java.math.BigInteger，可從字串建立大整數，並以 add 方法相加；一般的 int、long 仍有固定範圍，不會自動變成大整數。

10041 - Vito's Family

題目要求與解法重點

第一行是測試筆數。每筆測資給定親戚人數和各家的門牌，請替 Vito 選一個住址，讓他到所有親戚家的距離總和最小，並輸出這個總和。兩個門牌的距離是兩者相減後的絕對值；多人也可能住在同一個門牌。

選中位數當住址，再加總各家到它的距離，就能得到答案。 最容易理解的實作是先排序、再取中間的門牌；只需要找中位數時，也能用 nth_element 省去完整排序。剛開始學迴圈，則可以先逐一嘗試親戚家的門牌。

為什麼選中位數？奇偶數需要分開處理嗎？

中位數能讓絕對距離總和最小；本題不需要為偶數人數另外計算平均。 把門牌想成由小到大排列，將最左與最右的親戚配成一對：只要住址在兩者之間，到這一對的距離總和就相同。由外向內配對，選中間位置就能同時落在每對的區間內；奇數人時，還能讓正中間那位親戚的距離為零。這是中位數使絕對距離總和最小的性質。

以從 0 開始的索引 r / 2 取值，兩種人數都適用：

  • 奇數人，例如 2、4、6：取索引 1 的 4，距離總和為 2 + 0 + 2 = 4。
  • 偶數人，例如 2、4、6、8：取索引 2 的 6。其實選 4 到 6 之間任一位置，距離總和都是 8。

統計學通常將偶數筆資料的中位數定義為兩個中間值的平均；這題只要求距離總和最小，直接選其中一個中間門牌即可。下面的排序版與 nth_element 版都選較大的那一個。

三種做法怎麼選？

三種做法的差別在於如何找到最佳住址；選定住址後，都只要加總絕對距離。

做法 如何找住址 時間複雜度
暴力法 每個候選住址都算一次總距離，再取最小值 O(r²)
排序法 全部排序後取中位數 O(r log r)
選擇法 用 nth_element 找中位數 平均 O(r)

初學可先寫暴力法；理解中位數後，排序法最直觀；熟悉標準函式後，可用 nth_element 減少計算。 本題範圍小，三種做法都能通過，下面各附一份完整程式。

解法一：暴力枚舉候選住址

把每位親戚的門牌輪流當作候選住址，計算到所有親戚家的距離總和，再取最小值。外層迴圈選住址，內層迴圈累加距離。

只試親戚家的門牌就夠，因為奇數人時的中位數、偶數人時的兩個中間門牌，都在這些候選之中，一定不會漏掉最佳解。

若有 r 位親戚，共有 r 個候選，每個候選計算 r 次距離，時間為 O(r²)。題目的 r < 500，距離計算最多為 499 × 499 = 249001 次。

解法二：排序後取中位數

既然知道中位數就是最佳住址，就不必逐一嘗試候選。先用 std::sort 把門牌由小到大排序，取出 streetNumbers[streetNumbers.size() / 2]，再掃一次加總距離。

例如輸入門牌為 6、2、4，排序後是 2、4、6，選 4，距離總和為 4。

解法三：用 nth_element 找中位數

只需要中位數，不必知道其餘門牌的完整順序，因此可以改用 std::nth_element。 它會把指定位置放上「假如全部排好序，該位置應有的值」，但左右兩側各自不保證有序。

指定 streetNumbers.begin() + streetNumbers.size() / 2，呼叫後該位置就是前面要找的中間門牌。取出它的值，再加總各家到它的距離即可；加總不依賴陣列順序。

一般版本的 nth_element 平均需要 O(r) 時間，加上一次 O(r) 的距離加總，整體平均時間為 O(r)，不保證最壞情況也是線性時間。若需要全部門牌依序排列，仍應使用 sort。可參考 C++ 標準草案：nth_element。

382 - Perfection

題目要求

輸入是一串正整數，以 0 表示結束；每個數值介於 1 和 60000，輸入筆數 N 符合 1 < N < 100。對每個數字 n，加總所有小於 n、且能整除 n 的正整數，這些數就是本題要計算的真因數。比較總和與原本的數字 n：

  • 完美數（PERFECT）：真因數總和等於 n。例如 6 的真因數是 1、2、3，總和也是 6。
  • 豐沛數（ABUNDANT）：真因數總和大於 n。例如 12 的真因數是 1、2、3、4、6，總和為 16。
  • 不足數（DEFICIENT）：真因數總和小於 n。例如 9 的真因數是 1、3，總和為 4。

本題可直接檢查到 n - 1，也可以利用因數成對出現的性質，只檢查到 √n。兩種做法最後都依同一規則分類。

輸出第一行是 PERFECTION OUTPUT，最後一行是 END OF OUTPUT。每個數字要靠右對齊在 5 個字元內，後面接兩個空格與分類名稱。輸入值 1 沒有真因數，總和為 0，因此是不足數；結束標記 0 不分類也不輸出。

解法一：逐一檢查到 n − 1

從 1 到 n - 1，逐一檢查哪些數字能整除 n，把它們加起來即可。迴圈不包含 n，自然排除了數字本身；當 n = 1，迴圈不執行，總和維持為 0。

每個 n 最多檢查 n - 1 次，時間複雜度為 O(n)，額外空間為 O(1)。本題數值不超過 60000、輸入少於 100 筆，這個直接的做法也足夠。

當 n 是完全平方數，最後一對因數會相同。例如 36 的因數對為：

最後的 6 只是一個因數，不能因為寫成 6 × 6 就加兩次。因此程式先加 d，再判斷 n / d != d，不同時才加入另一個因數。正確總和是 1 + 2 + 18 + 3 + 12 + 4 + 9 + 6 = 55。

程式如何排除 n 本身？

先處理 n = 1，直接回傳 0。對其他數字，先將總和設為 1，再從 d = 2 開始找因數。這樣 1 × n 這一對只會加入 1，不會誤加 n。

迴圈條件使用 d * d <= n，等同只檢查到 √n，也會包含完全平方數的平方根，不需要另外呼叫開根號函數。本題 n <= 60000，這個條件中的乘法使用 32 位元 int 足夠。

C++11 程式：成對找因數

這份根號版本以 C++11 提交至 UVa 382，獲得 Accepted（submission 31362904，0.000 秒）。

每個 n 的時間複雜度為 O(√n)，額外空間仍為 O(1)。當 n = 60000，只需檢查 d = 2 到 244，相較直接檢查 1 到 59999，可省下許多次整除判斷。

兩種做法怎麼選？

剛開始學迴圈與取餘數，可以先寫逐一檢查的版本；理解因數成對出現後，就能改用根號版本減少計算量。兩種做法都要排除 n 本身，而根號版本還要注意完全平方數不能重複加上平方根。

比賽時，若題目給定的資料範圍小，簡單的做法就能在時間限制內完成，可以優先選擇容易實作、較不容易寫錯的方法。本題兩個版本在 UVa 的執行時間都顯示為 0 ms，因此直接逐一檢查也是合理的選擇。

不過，0 ms 不代表兩者的計算量相同；根號版本的複雜度較低，當資料範圍變大時，更能發揮優勢。選擇時應先依題目範圍估算計算量，而不是只看這次判題顯示的時間。

483 - Word Scramble

題目要求

輸入是多行文字；每個單字都是一段連續的非空白字元。請反轉每個單字內的字元順序，但保留單字原本的排列、空白和換行。例如 I love you. 會變成 I evol .uoy，句點也會跟著單字一起反轉。

解法

用 getline 一次讀一行，再由左向右尋找非空白字元組成的區段。找到一個單字後，只反轉這段字元，接著從區段後面繼續掃描。空格、Tab 等分隔字元不會移動，因此行內的空白排列也會保留。

若一行有 L 個字元，掃描與反轉合計需要 O(L) 時間；字串需要 O(L) 空間。每個字元只會被掃描一次，並且只在所屬單字的區段內交換位置。

注意：保留換行與單字之間的空白

官方題目以空白字元分隔單字，但沒有保證單字之間只有一個空格。因此不假設分隔空白的數量，讓它們留在原位即可。

直接用 cin >> word 讀單字時，空格、Tab 和換行都會被略過。只看讀出的單字，無法知道原本在哪裡換行，也無法還原單字之間有幾個空格。

先用 getline 讀一整行，再用 stringstream >> word 切單字，可以保留行的界線，但仍會丟掉行內分隔空白的數量與種類。例如自訂的這一行有三個空格：

若讀出 ab、cd 後統一補一個空格，就會變成 ba dc，改變原本的排列。

本文採用 getline 加上原字串內的區段搜尋：讀入一行後，找出每個單字的起點與終點，只反轉這段字元，空格和 Tab 都留在原位；處理完再輸出換行。這樣既保留行的界線，也不必重新組合單字之間的空白。

另外也可以用 cin.get(ch) 逐字元讀取，自行辨識單字與分隔字元；並非一定要用 getline + stringstream 才能處理換行。

10079 - Pizza Cutting

題目要求

輸入每次給一個整數 n，代表要用幾條直線切披薩，求最多能切出幾塊。n 為非負數，且不超過 210000000；負數表示輸入結束。每筆答案各輸出一行。

解法

最多區塊數為 n(n + 1) / 2 + 1。從一塊完整披薩開始，第 k 條切線若與前面 k - 1 條線都在披薩內相交，而且交點彼此不同，就會被分成 k 段。每一段都能切開一個原有區塊，因此新增 k 塊。

以第三刀為例：前兩刀已把披薩分成四塊。下圖的紅色第三刀在披薩內，與前兩刀分別交於 A、B，且不經過前兩刀原本的交點。

這張圖為自行繪製的切割示意。兩個交點把第三刀分成三段，每段各切開一個原有區塊，因此新增三塊，從四塊變成七塊。下面的表格整理了同樣的規律：

切線數 新增區塊 區塊總數
0 0 1
1 1 2
2 2 4
3 3 7

所以切 n 條線後，區塊數為 1 + 1 + 2 + ... + n，也就是 n(n + 1) / 2 + 1。程式直接代入公式，不需要模擬切割。題目最大輸入下，答案約為 2.21 × 10^16，因此使用 long long 保存。

每筆輸入只做固定次數的整數運算，時間與額外空間複雜度都是 O(1)。
