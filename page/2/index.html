10878 - Decode the Tape

UVa 10878 要把紙帶上的孔洞還原成文字。每列代表一個字元；程式從每列的 8 個資料位元重建字元，並在讀到第二條 ___________ 時停止。

每列轉成一個字元

每列左右兩端的 | 是紙帶邊界，中間的 . 用來標示中心位置。略過邊界和點號後，剩下的位置由左至右代表位元 7 到位元 0。讀到 o 就把該位設為 1，讀到空白則設為 0。

程式以從 0 開始的字串索引讀取固定欄位：左右邊界在 row[0] 和 row[10]，中央的 . 在 row[6]；資料位元位於 row[1] 到 row[5]，以及 row[7] 到 row[9]。因此迴圈檢查索引 1 到 9，並略過索引 6。

題目沒有明說這 8 個位元要用哪種字元編碼。可以從範例推知：官方範例第一列讀成 01000001₂，換算為十進位是 65；依 ASCII 對應為 A，正好是範例訊息的第一個字元。因此本文按 ASCII 解碼，但要注意這項規則是從範例推得，題目敘述沒有明文交代。

程式由左至右逐位累積：先把目前值左移一位，再放入新位元。以 01000001 為例，讀完前兩位後目前值是 1；再讀入 0 時，先左移得到 2，再加入 0，後續位元依此類推，最後得到 65。

輸入的第一條 ___________ 是紙帶起點；之後每讀到一列就輸出一個字元，直到讀到下一條分隔線。這樣每列都會解碼一次，並保留訊息中的空格、標點和換行字元。

C++11 程式

每列處理固定 8 個資料位元，因此共有 N 列時，時間為 O(N)；程式只保存目前一列和一個位元組，額外空間為 O(1)。

驗證

整理版以 MSYS2 UCRT64 g++、-std=c++11 -Wall -Wextra -pedantic 編譯；以程式產生 0 到 127 的 ASCII 紙帶列，解碼結果逐位元組相符。另用 uDebug 提供的完整紙帶資料解碼，結果與 Accepted Output 相符（將文字欄位正規化的換行形式統一後）。UVa 題目敘述 · uDebug 測資

本篇程式以 C++11 提交 UVa 10878，結果為 Accepted。

10167 - Birthday Cake

UVa 10167 要用直線把圓形蛋糕切成形狀相同的兩半。蛋糕上有 2N 顆櫻桃，切開後每一半都要有 N 顆，切割線上也不能有櫻桃。要讓兩半形狀相同，切割線必須通過圓心 (0, 0)。將切割線寫成 Ax + By = 0，就能根據每顆櫻桃的 Ax + By 正負判斷它位於哪一側，再搜尋符合條件的整數係數 A、B。

用內積判斷櫻桃在哪一側

一般直線可寫成 Ax + By = C。本題的切割線必須通過原點 (0, 0)，因此 C = 0，直線方程式是 Ax + By = 0。向量 (A, B) 是這條直線的法向量，也就是垂直於直線的向量。對每顆櫻桃的座標 (x, y)，計算它與 (A, B) 的內積 (A, B) · (x, y) = Ax + By。這個內積值大於 0 表示櫻桃在法向量所指的一側，小於 0 表示在另一側；等於 0 則表示櫻桃在線上，這組係數不能使用。

例如官方範例的 N = 2，四顆櫻桃的座標是 (-20, 20)、(-30, 20)、(-10, -50)、(10, -5)。取 (A, B) = (0, 1) 時，切割線是 y = 0，內積值就是各點的 y 座標。前兩顆位於直線上方，後兩顆位於下方，因此兩側各有兩顆櫻桃。

下圖把這個切割方式畫在圓形蛋糕上：綠色箭頭是法向量 (A, B) = (0, 1)，與水平切割線 y = 0 垂直。藍色點在直線上方，橘色點在下方；右側列出每顆櫻桃的座標和內積值，方便對照正負號與位置。

搜尋係數

題目保證每組輸入至少有一組解，且 A、B 都在 [-500, 500]；兩者不能同時為 0，否則方程式不代表一條直線。又因為 N ≤ 50，最多只有 100 顆櫻桃，所以可以枚舉係數，逐一檢查每顆櫻桃。(A, B) 與 (-A, -B) 表示同一條線，只會把正、負兩側對調；因此只搜尋 A ≥ 0 不會漏掉答案。當 A = 0 時，方程式變成 By = 0，只要 B 不為 0，就等同於 y = 0，因此只需檢查 (0, 1)。題目接受任一組符合條件的答案，找到第一組就可以輸出。

檢查一組係數時，如果發現櫻桃在線上，就停止檢查這組係數；如果任一側已經超過 N 顆，也可以提早停止，因為後續櫻桃無法讓數量平衡。找到兩側各有 N 顆櫻桃的係數後，就輸出答案。利用 (A, B) 與 (-A, -B) 的對稱性後，最多檢查約五十萬組係數；每組最多檢查 2N ≤ 100 顆櫻桃，最壞情況約要判斷五千萬次櫻桃位於切割線哪一側，因此直接搜尋就足以應付本題。時間複雜度為 O(500^2 N)，額外空間為 O(N)。

C++11 程式

驗證

整理版以 MSYS2 UCRT64 g++、-std=c++11 -Wall -Wextra -pedantic 編譯，通過官方範例及自建案例。uDebug 提供 256 組測資；由於本題允許多組答案，逐組依題目條件檢查係數範圍、切割線上沒有櫻桃，且兩側各有 N 顆。UVa 題目敘述 · uDebug 測資

本篇程式以 C++11 提交 UVa 10167，結果為 Accepted，執行時間 0.010 秒。

10125 - Sumsets

每筆輸入是一組互不相同的整數：先給元素數量 n（1 ≤ n ≤ 1000），再給 n 個整數；輸入以 n = 0 結束。從集合中選出四個不同的數值 a, b, c, d，使 a + b + c = d。如果有多組答案，輸出最大的 d；若沒有答案，輸出 no solution。

解法摘要

將 a + b + c = d 改寫成 a + b = d - c。由大到小嘗試 d，對每個 c 查詢是否有兩個數的和等於 d - c。為了加速這些查詢，先建立所有兩數和並排序，再用 binary search（二分搜尋）找目標值；每筆和都保留組成數對的索引，以排除重複使用元素。最壞時間複雜度為 O(n² log n)，額外空間複雜度為 O(n²)。

從 2SUM、3SUM 到 4SUM

2SUM：給定一組數和目標和 t，找兩個不同的數 a、b，使 a + b = t。數列排序後，可以用雙指標在 O(n) 時間回答一次查詢。

3SUM：給定目標和 t，找三個數使總和等於 t。固定其中一個數 a，剩下的問題就是目標為 t - a 的 2SUM；排序後逐一固定 a，總時間為 O(n²)。

4SUM：給定目標和 t，找四個數使總和等於 t。把四個數分成兩對，可改寫成 x₁ + x₂ = t - (x₃ + x₄)。預先建立所有數對的和，再查詢互補的和，就能把直接枚舉四個數的 O(n⁴) 降為 O(n² log n)，代價是使用 O(n²) 空間。

本題和 4SUM 一樣要選四個互異的數，但右側的 d 也必須來自集合，且題目要求最大的 d。因此可以把每個候選 d 看成一次目標值為 d 的 3SUM；更進一步固定 d 和 c，就得到目標值為 d - c 的 2SUM。這個轉換讓我們能把所有 2SUM 查詢共用同一張兩數和表。

以官方範例 2, 3, 5, 7, 12 為例，先嘗試最大的 d = 12。固定 c = 2 後，目標值是 12 - 2 = 10；數對 (3, 7) 的和為 10，而且四個數互異，因此答案是 12。

如何選擇查詢方法

d、c 都要從集合中選，最多會有 n(n - 1) 組候選，也就是最多 O(n²) 次 2SUM 查詢。可以按下列方式選擇每次查詢的演算法：

做法 單次 2SUM 查詢 最壞總時間 額外空間 取捨
每次掃描全部數對 O(n²) O(n⁴) O(1) 寫法直接，但查詢很多時較慢
排序原數列後用雙指標（跳過 c、d） O(n) O(n³) O(1) 省空間，需為每組 (d, c) 重做查詢
預先建立並排序兩數和，再用二分搜尋 O(log n) O(n² log n) O(n²) 多用空間，換取較低的最壞時間；本解法採用此方法

若優先省記憶體，可以選排序加雙指標，接受 O(n³) 的最壞時間。這題的 n 最大為 1000，兩數和表最多有 499,500 筆；因此本解法使用 O(n²) 空間預存結果，將最壞時間降為 O(n² log n)。而題目只要求最大的 d，所以由大到小測試 d，一找到答案即可停止；若高 d 很快找到，實際查詢會更少，但無解時的最壞複雜度不變。

如何確保四個數互異

兩數和表找到總和符合的數對後，還要確認它沒有重用 c 或 d。否則雖然和正確，仍不符合四個數互異的要求。

題目保證輸入的數值互不相同。固定目標和 t = d - c 後，若數對包含 c，另一個數只能是 t - c = d - 2c，所以最多只有一組數對會包含 c；若數對包含 d，另一個數只能是 t - d = -c，所以最多只有一組會包含 d。因此最多兩組數對會因為重用 c 或 d 而無效。若 (c, d) 本身也剛好是目標和為 t 的數對（例如 c = 0），它會同時落在這兩類，但仍只算一組無效數對。

所以，如果同總和至少有三組數對，檢查其中前三組就一定能找到有效數對；如果只有一組或兩組，則要逐組檢查索引，確認是否有一組避開 c、d。

回到集合 { -2, -1, 0, 1, 2, 3, 4, 5 } 的例子，固定 d = 5、c = 2，程式中的查詢目標 target（以下記作 t）是 d - c = 3。兩數和表中，總和等於 t 的數對如下：

數對 檢查結果 原因
(-2, 5) 排除 重用了 d = 5
(-1, 4) 可用 沒有重用 c 或 d
(0, 3) 可用 沒有重用 c 或 d
(1, 2) 排除 重用了 c = 2

程式用 lower_bound 找到第一筆總和等於 t 的紀錄，接著最多檢查三筆同總和的數對；如果數對索引等於 c 或 d 就跳過，否則表示找到答案。表格中的數對順序可能不同，但最多只有兩筆會被排除，所以前三筆中一定有可用的數對。程式函式的參數名稱 target 就是這裡的 t。

複雜度

令兩數和表的大小為 M = n(n - 1)/2。建立表需要 O(n²) 時間，排序需要 O(M log M) = O(n² log n)；最多查詢 O(n²) 次，每次二分搜尋為 O(log M) = O(log n)。因此整體時間複雜度是 O(n² log n)，額外空間複雜度是 O(n²)。原數列排序的 O(n log n) 比表的排序成本低階，不影響總複雜度。

C++11 程式

驗證

整理版以 MSYS2 UCRT64 g++、-std=c++11 -Wall -Wextra -pedantic -O2 編譯。官方範例、邊界案例、200 組隨機小資料（與暴力解比對）及 n = 1000 無解案例均通過。uDebug 的 6 組輸入中，5 組已直接用編譯後執行檔比對；第 4 組有 50 筆資料，在頁面內逐筆計算後與 50 行 Accepted Output 全數相符，但完整輸入尚未直接餵給本機執行檔。

296 - Safebreaker

UVa 296 是類似「幾 A 幾 B」的四位數猜密碼題。可以把 0000 到 9999 想成候選清單：每條猜測都附有一組 A/B 線索，我們逐條排除不符合的候選。最後剩下 0 個、1 個或多個候選，就分別輸出 impossible、密碼或 indeterminate。

A/B 線索怎麼判斷

A 表示數字和位置都正確；B 表示數字正確，但位置錯誤。假設秘密是 3321，猜測 1223：只有第三位的 2 相同，所以 A = 1。猜測和秘密都含有 1、2、3 各一個，合計有 3 個數字相符；扣掉位置正確的 1 個，得到 B = 2，所以線索是 1/2。

計算相符數量時要考慮重複數字。猜測裡即使有兩個 2，秘密只有一個 2，也只能算一個相符；因此每個數字依兩邊實際出現次數配對，最多配對 min(猜測次數, 秘密次數) 次。

逐條排除候選

候選清單是解題的想法，程式不必真的存下 10,000 個數。只要依序檢查 0000 到 9999，對每個候選逐條計算 A/B；有一條線索不符就排除，通過全部線索才保留。找到第二個候選時就能確定是多解，不必再檢查後面的數字。

密碼可能以 0 開頭。程式把猜測讀成四個字元，並將數字候選拆成四位，所以 0000 也會保留完整位數；輸出唯一答案時則固定補成四位數。

C++11 程式

對每個候選密碼，最多檢查 10 條線索；每條線索只需比較 4 個位置與 10 種數字的出現次數。因此單筆測資的時間複雜度為 O(10^4 G)，其中 G ≤ 10；額外空間為 O(G)。

驗證

整理版以 C++11 和 -Wall -Wextra -pedantic 編譯通過，官方範例輸出為 3411、1234、indeterminate、impossible。自建案例也涵蓋 0000 的前導零輸出、重複數字、互相矛盾的線索和沒有任何線索時的多解判定。

舊版有三筆 uHunt 紀錄：submission 10665198 和 10665202 為 Wrong Answer，submission 10665259 Accepted。整理版另以 C++11 提交，submission 31355530 Accepted，0.020 秒。UVa 題目敘述

311 - Packets

UVa 311 給出六種正方形包裹的數量，尺寸從 1×1 到 6×6；要把它們裝進 6×6 的箱子，並使用最少的箱子。解法是由大到小安排：先計算 6×6、5×5 和 4×4 包裹，再處理 3×3、2×2，最後把剩下的 1×1 裝箱。

每筆輸入依序給出 1×1 到 6×6 包裹的數量，六個數量全為 0 時結束。大尺寸包裹放進箱子後會留下固定形狀的空位，因此可以直接計算小包裹能填多少空間，不必真的模擬擺放位置。

先安排較大的包裹

每個 6×6 包裹剛好占一箱。每個 5×5 包裹也要一箱，箱內剩下 11 個 1×1 空位，可以優先放入 1×1 包裹。

一個 4×4 包裹占一箱，剩下的空間可以放 5 個 2×2 包裹。如果手上的 2×2 不足，每少一個 2×2，就能多放 4 個 1×1。整理時把這些空位從待裝的 1×1 數量中扣除。

處理 3×3 包裹

四個 3×3 包裹剛好放滿一箱。若不足四個，剩下的包裹各需要一箱，並留下以下空位：

箱內的 3×3 數量 可放的 2×2 數量 若 2×2 都放滿，還可放的 1×1 數量
1 5 7
2 3 6
3 1 5

若 2×2 不足，每個缺少的 2×2 空位可以改放 4 個 1×1；因此也能直接更新剩下待裝的 1×1 數量。

裝入 2×2 和 1×1

一箱最多放 9 個 2×2。若最後一箱沒有裝滿，剩下的位置可放入 1×1：每個缺少的 2×2 位置可換成 4 個 1×1。處理完 2×2 後，每箱最多再裝 36 個 1×1，所以箱數是 ceil(剩餘數量 / 36)。

C++11 程式

每種尺寸只處理一次，時間和額外空間都是 O(1)。程式以 long long 保存包裹數，並在最後一個尺寸也讀入後才判斷六個 0 的結束資料。

驗證

整理版以 C++11 和 -Wall -Wextra -pedantic 編譯通過；官方範例輸出 2、1。另以 5,000 組隨機輸入和保留的舊 Accepted 程式比對，輸出一致；邊界案例涵蓋 1×1、2×2 的滿箱與超出一個，以及各種較大包裹留下的空位。

舊版 submission 10724587 為 Accepted（C++，0.016 秒）。本文整理程式經本機測試，沒有重新提交。UVa 題目敘述

714 - Copying Books

UVa 714 要把依序排列的書分給 k 位抄寫員。每人拿到的書必須連續，而且至少一本；目標是讓工作量最大的人所負責的頁數盡量少。若有多種最佳分法，則讓前面的抄寫員依序拿較少的頁數。

先猜一個工作量上限 L，再由左到右裝書：如果下一本會讓目前抄寫員超過 L，就交給下一位。若這樣用到不超過 k 位抄寫員，L 就可行。可行性具有單調性：上限越大，越容易裝完，因此用二分搜尋找最小可行上限。

二分搜尋工作量上限

最小上限不可能小於最厚的一本書；最大上限則是所有書頁數的總和。對每個測試值 L，從第一本開始累加頁數，超過 L 時才切給下一位抄寫員。若需要的人數不超過 k，表示 L 可行；否則提高下限。

題目要求分成恰好 k 組，而可行性檢查只確認最多用 k 組。由於每本書都必須分配，且 k ≤ m，若檢查結果少於 k 組，就能再把已有的組拆開，直到剛好 k 組，且不會增加任何一組的頁數。

決定分界與平手順序

找到最小上限後，從最後一本往前安排。只要再加入一本會超過上限，就在目前位置切開；若剩下的書本數不足以讓每位尚未分配的抄寫員至少拿一本，也必須切開。

從右往左盡量裝滿，可以讓右側組別盡可能大，讓第一位抄寫員拿到的頁數盡可能少；固定第一組後，同樣的方式也讓第二組盡量少，符合題目的平手規則。

C++11 程式

若書本數為 m、總頁數為 S，每次可行性檢查需要 O(m)，二分搜尋需要 O(log S) 次檢查；整體時間複雜度為 O(m log S)，空間複雜度為 O(m)。頁數總和可能超過 32 位元整數範圍，因此使用 long long。

驗證

整理版以 C++11 和 -Wall -Wextra -pedantic 編譯通過；官方範例輸出與題目相同。另以暴力枚舉所有分界，檢查 1,200 組小型隨機資料的最小最大頁數和平手順序，結果一致；也通過 500 本書、總頁數超過 32 位元整數範圍的案例。

10464 - Big Big Real Numbers

UVa 10464 給定多組十進位數，每組有兩個數，請輸出它們的和。數字可能是負數，小數點前和小數點後都可能各有 1000 位；答案要省略多餘的前導零與小數末尾零，且小數點兩側都至少留一位。例如 004112.000 + 21.00 要輸出 4133.0。

解法的核心是：把兩個數轉成同一尺度的帶符號整數字串，完成加減後再放回小數點。 這樣能精確處理長數字，不會有浮點誤差。

先把小數表示成整數字串

題目允許每個數的小數點前、後各有 1000 位。題目敘述 因此固定把小數位補到 1000 位，相當於將原數乘上 10^1000，再移除小數點。例如 12.34 會表示成 1234 後接 998 個零。整數字串另外記錄正負號。

接著只需要對整數字串做加法或減法：加法從右向左逐位相加並傳遞進位；減法同樣從右向左處理借位，並先確保較大的絕對值在前。兩個字串長度可以不同，直接從右端對齊即可。

根據符號決定加減

先分開處理符號，是為了讓逐位運算只處理非負的數字。異號相加時先比較絕對值，再用大的減小的，借位過程就不會產生負的中間結果；算完後再依絕對值較大的那一項決定結果符號。同號時則直接相加絕對值。

符號與大小 絕對值運算 結果符號
a、b 都是正數 abs(a) + abs(b) 正
a、b 都是負數 abs(a) + abs(b) 負
異號，abs(a) > abs(b) abs(a) - abs(b) 跟 a 相同
異號，abs(a) < abs(b) abs(b) - abs(a) 跟 b 相同
異號，abs(a) = abs(b) 零 輸出 0.0

例如 3.3 + (-1.1) 會計算 abs(3.3) - abs(-1.1)，結果沿用 3.3 的正號；-1.1 + 3.3 則沿用 3.3 的正號。絕對值相同時直接輸出 0.0，不產生負零。

還原小數點並整理輸出

計算結果仍代表原數乘上 10^1000。從右側切出最後 1000 位作為小數部分，移除整數部分的前導零和小數部分的末尾零；兩部分各至少保留一位。
