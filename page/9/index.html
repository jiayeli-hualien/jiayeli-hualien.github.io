1.mu(1)=1, by definition;

2.if N is not square free, mu(N)=0;

3.if N is square free and contains an even number of prime factors, mu(N)=1;

4.if N is square free and contains an odd number of prime factors, mu(N)=-1.

解法

1.mu(1) = 1

2.not square free 很容易被檢查出來

3.not square free的倍數一定也是not square free

4.square free的數字可以乘上非自己因數的數字得出，mn(Nm) = mn(n)-1

5.若無法從前面推出來 就做質因數分解

三種情形

1.分解至1

  1. 分解至大質數 > 1000

3.連續整除not square free

6.使用Memoization

10613 - Mushroom Misery //真菌增生!?

初版驗證狀態：尚未完成目前程式與原始 Accepted 紀錄的比對；後續確認後會補上驗證資訊。

我是在演算法筆記上看到這題的。

 

題目的大意就是，給你N，有個N*N的範圍。接著長出了許多真菌，分別給你圓心與半徑，要計算出被覆蓋的方格數量。方格數量接近CPU 1秒能處理的計算量的極限。

 

 

 

然後從UVA官方討論區看到解法如下：

將圓切成矩形

 

　　顧名思義就是把圓形變矩形，我的作法是先將圓形變成一條一條的長方形，之後使用演算法筆記當中的「舉例：宴會中訪客數目的極大值（ Interval Partitioning Problem ）」，排序進出順序，並將「無矩形覆蓋方格變成有矩形覆蓋方格，再變回無矩形覆蓋方格」的發生點抓出來，透過相減得到覆蓋格數。如圖示，詳細運作過程可看演算法筆記。

 

 

那麼如何取出in跟out的地點呢?

 

設半徑為r，先找某個離圓心很近的水平線，向外延伸 r 格，之後利用畢氏定理與高斯符號求出左右延伸的範圍。

更細一步講，我將整個圓分成上區、下區、mid區去計算，另外還有許多差一格、超出邊界之類的實作細節就不贅述了。

 

總結：

  1. 將圓切成很多條長方形
  2. 一行一行處理in out的點，統計覆蓋格數

題目：UVa 10044 - Erdös Numbers

解法

程式以作者為節點建立無向圖：同一篇論文中的作者彼此相連。ParseName() 將論文作者拆成名字並取得編號，setRelation() 為共同作者建立邊；接著從 Erdos, P. 執行 BFS，得到每位作者到 Erdos 的最短共同發表距離。查詢作者若不在圖中或沒有連通，就輸出 infinity。

作者解析參考：原文列出的字串解析程式；BFS 資料：Algorithmist。

這份舊碼有待修正的情況：若資料庫中沒有 Erdos, P.，nameToIndex["Erdos, P."] 會預設插入編號 0，錯把第一位作者當成 BFS 起點；此外 input() 宣告回傳 int，但函式結尾沒有回傳值。修正後再提交 UVa；程式碼先保留。

10205 - Stack ‘em Up

Problem E: Stack ‘em Up

一疊標準撲克牌包含52張卡片，有13種點數與4種花色。13種值為2、3、4、5、6、7、8、9、10、Jack、Queen、King、Ace。四種花色為Clubs、Diamonds、Hearts、Spades。不同的卡片以點數、花色識別，格式為 <點數> of <花色>，例如：”9 of Hearts” or “King of Spades”。一般來說一副新牌會按照順序先排序花色再排序點數。

大城市裡有很多賭場。某間賭場的一位發牌員詐賭。他有幾種特定的洗牌方法；每種洗牌方式會用一個特別的規則將牌重新排序。一個簡單的例子是「切牌」，把底部的牌洗到上面。組合多種已知的洗牌套路，詐賭的發牌員可以將牌洗成特定的順序。

你被保安人員留下來跟監這位發牌員。你拿到了列有發牌員所有洗牌模式的表，你必須觀察發牌員的動作並猜測他正在使用哪一種洗牌方式。你的工作是預測牌組，在發牌員數次洗牌動作後撲克牌的順序。

輸入

輸入的第一行只有一個正整數。表示接下來有幾組測試資料。第二行是空行，任兩組測試資料之間也有一行空行。

每組輸入包含一個正整數 n <= 100，代表有 n 種洗牌方式。然後有52個整數跟在 n 後面。

每52個數字，會將1到52以特別的順序排出。這52個數字代表著洗牌的方式，數字 i 在位置 j 表示要將第 i 張牌移到第 j 個位置。

(例16 32 18…… 代表要把第16張排放到第1張，把第32張牌放到第2張，把第18張排放到第3張……

接下來會有好幾行，行數不定。每行包含一個數字k，數字k介於1~n之間，代表你觀察到發牌員使用第k種方式洗牌。

843 - Crypt Kicker//密碼 回溯法

初版驗證狀態：尚未完成目前程式與原始 Accepted 紀錄的比對；後續確認後會補上驗證資訊。

回溯法

演算法筆記http://www.csie.ntnu.edu.tw/~u91029/Backtracking.html

解題:

找一種組合，使密碼裡的所有單字對應到字典裡的單字。限制條件:每個字母都是一對一的關係，如果a對應到b則a不可以對應到c，其他字也不能對應到b。

題目的input表示每個單字的長度不會超過16，字典單字總數不超過1000，每行密文長度不超過80。意思就是說用暴力法解OK。

1.把字典存起來。

2.讀入一行密文。將密文拆成單字。

3.使用回溯法嘗試各種可能，把密文的所有單字對應到字典裡的單字。

甚麼是對應?

使用範例輸入

bjvg xsb hxsn xsb qymm xsb rqat xsb pnetfn

例如hxsn必須對應到dick時

h -> d 會發現，d 已被 b 使用，所以無法對應。

另外x已對應到a，這種狀況也會造成無法對應。

例能對應的情況

目前bjvg已對應到dick

xsb需要對應到and時，x、s尚未有對應的字母(都對應*)。

b對應d，剛好符合xsb要對應到and。

x -> a

s -> n

b -> d

三個都可以建立。

回溯法函數的想法是：

1.嘗試所有可能。例如遇到hxsn時，嘗試所有長度為4的字串。

  1. 若找到可以對應的字則處理下一個密文單字。→ 若從下一步退回來，嘗試其他長度為 4 的字串，直到嘗試所有字串。

3.嘗試完所有可能，退回上一步。

備份與恢復

回溯法必須記錄目前的狀況，方便以後向後退時能夠繼續嘗試其他可能。
