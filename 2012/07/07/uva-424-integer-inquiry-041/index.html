424 - Integer Inquiry

用大整數加法求總和

輸入多個非負整數，最後一行的 0 表示輸入結束，請輸出所有數字的總和。題目最多有 100 個數，每個數最多 100 位，連 long long 也放不下。

解法是用陣列分開保存各位數，再像直式加法一樣相加與進位。 先用字串讀入完整數字，就不必把整個數值塞進單一整數變數。本篇先用「陣列一格存一位」說明原理，程式再採用「一格存四位」減少需要處理的格數。

就像直式加法

例如 999 + 2，從個位開始相加，滿 10 就向左進位：

  999
+   2
-----
 1001

個位的 9 + 2 = 11，保存 1、進位 1；十位與百位都因為接到進位而得到 10，各保存 0、繼續進位，最後得到 1001。大整數加法就是把這個過程寫成程式。

先從陣列一格存一位開始

將 999 存成 [9, 9, 9, 0, …]，2 存成 [2, 0, 0, 0, …]。索引 0 保存個位，索引 1 保存十位，依此類推。這樣迴圈從索引 0 往後走，就能按照低位到高位的順序處理。

每格計算 total = 原有數字 + 新數字 + carry，其中 carry 是前一格傳來的進位：

這裡的除法是整數除法。例如 11 % 10 = 1、11 / 10 = 1，正好對應「保存 1、進位 1」。算完 999 + 2，陣列會是 [1, 0, 0, 1, 0, …]；輸出時由高位往低位讀，就得到 1001。

程式為什麼一格存四位？

一格一位已經能解這題。一格四位則把相鄰的四個十進位數字合成一段，讓需要處理的格數約縮成四分之一；加法與進位的原理相同，只是由滿 10 進位，改成滿 10000 進位。

例如 123456789 從右側每四位切一段，得到 1、2345、6789，陣列反向存成 [6789, 2345, 1, 0, …]，讓索引 0 仍代表最低段。每段的值介於 0 到 9999。

對應到程式，BASE = 10000，每段計算：

以 99999999 + 2 為例，每四位一組的直式加法如下：

   9999 9999
+         2
-----------
1  0000 0001

每組滿 10000 就向左進位，結果是 100000001，陣列存成 [1, 0, 1, 0, …]。程式每次都先合併低位並向高位進位，已處理的段就會保持在 0 到 9999 之間；讀完所有輸入後，陣列保存的就是完整總和。

加法安全，乘法也安全嗎？

本題一次把一個新數字加進總和，每段相加連同進位，最大為 9999 + 9999 + 1 = 19999，使用 32 位元 int 足夠。

若改做乘法，就要重新估算中間值，不能直接沿用加法的安全範圍。 單次兩段相乘最多為 9999 × 9999 = 99980001，仍放得進 32 位元 int；但如果先把多個乘積累加到同一格、最後才進位，就可能溢位。例如累加 50 個最大乘積會得到 4999000050，已超過 2147483647。

因此，寫乘法時要連同累加項數與進位估算上限，再決定分段大小、中間值型別和進位時機。若需要 long long，也要讓乘法在該型別下進行，例如 1LL * a[i] * b[j]，而不是等乘法算完才轉型。本題只有加法，目前的四位分段與 int 已足夠。

輸出與容量

最高的非零段直接輸出，其餘較低的段都固定補成四位，才能保留每段的位置。例如 [1, 1] 要由高到低印成 1 接上 0001，得到 10001，不能直接接成 11。上面的連續進位例子則印出 1、0000、0001，接起來才是 100000001。

若總和為 0，仍保留並輸出索引 0 的段，避免往陣列範圍外尋找非零段。輸入即使帶有前導零，輸出也會自然省略多餘的零。

程式使用 50 段的容量，可保存 200 位十進位數字。題目最多將 100 個 100 位數相加，總和最多 102 位，因此容量足夠。

競賽時也可以用語言提供的大整數

若競賽允許使用 Python，這題可以直接把輸入字串轉成 int 再累加，不必自行分段與處理進位。Python 的 int 支援任意精度整數，可以保存本題的 100 位數與總和。

Java 的標準函式庫則提供 java.math.BigInteger，可從字串建立大整數，並以 add 方法相加；一般的 int、long 仍有固定範圍，不會自動變成大整數。
