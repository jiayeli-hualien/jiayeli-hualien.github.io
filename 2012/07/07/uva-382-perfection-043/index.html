382 - Perfection

題目要求

輸入是一串正整數，以 0 表示結束；每個數值介於 1 和 60000，輸入筆數 N 符合 1 < N < 100。對每個數字 n，加總所有小於 n、且能整除 n 的正整數，這些數就是本題要計算的真因數。比較總和與原本的數字 n：

  • 完美數（PERFECT）：真因數總和等於 n。例如 6 的真因數是 1、2、3，總和也是 6。
  • 豐沛數（ABUNDANT）：真因數總和大於 n。例如 12 的真因數是 1、2、3、4、6，總和為 16。
  • 不足數（DEFICIENT）：真因數總和小於 n。例如 9 的真因數是 1、3，總和為 4。

本題可直接檢查到 n - 1，也可以利用因數成對出現的性質，只檢查到 √n。兩種做法最後都依同一規則分類。

輸出第一行是 PERFECTION OUTPUT，最後一行是 END OF OUTPUT。每個數字要靠右對齊在 5 個字元內，後面接兩個空格與分類名稱。輸入值 1 沒有真因數，總和為 0，因此是不足數；結束標記 0 不分類也不輸出。

解法一：逐一檢查到 n − 1

從 1 到 n - 1，逐一檢查哪些數字能整除 n，把它們加起來即可。迴圈不包含 n，自然排除了數字本身；當 n = 1，迴圈不執行，總和維持為 0。

每個 n 最多檢查 n - 1 次，時間複雜度為 O(n)，額外空間為 O(1)。本題數值不超過 60000、輸入少於 100 筆，這個直接的做法也足夠。

每一對因數，至少有一個不大於 √n。 因為如果兩個都大於 √n，乘積就會大於 n，不可能是 n 的因數對。因此，只要檢查到 √n，每找到一個因數 d，就可以同時找到另一個 n / d；不必再把較大的因數逐一檢查一遍。

最後的 6 只是一個因數，不能因為寫成 6 × 6 就加兩次。因此程式先加 d，再判斷 n / d != d，不同時才加入另一個因數。正確總和是 1 + 2 + 18 + 3 + 12 + 4 + 9 + 6 = 55。

程式如何排除 n 本身？

先處理 n = 1，直接回傳 0。對其他數字，先將總和設為 1，再從 d = 2 開始找因數。這樣 1 × n 這一對只會加入 1，不會誤加 n。

迴圈條件使用 d * d <= n，等同只檢查到 √n，也會包含完全平方數的平方根，不需要另外呼叫開根號函數。本題 n <= 60000，這個條件中的乘法使用 32 位元 int 足夠。

每個 n 的時間複雜度為 O(√n)，額外空間仍為 O(1)。當 n = 60000，只需檢查 d = 2 到 244，相較直接檢查 1 到 59999，可省下許多次整除判斷。

兩種做法怎麼選？

剛開始學迴圈與取餘數，可以先寫逐一檢查的版本；理解因數成對出現後，就能改用根號版本減少計算量。兩種做法都要排除 n 本身，而根號版本還要注意完全平方數不能重複加上平方根。

比賽時，若題目給定的資料範圍小，簡單的做法就能在時間限制內完成，可以優先選擇容易實作、較不容易寫錯的方法。本題兩個版本在 UVa 的執行時間都顯示為 0 ms，因此直接逐一檢查也是合理的選擇。

不過，0 ms 不代表兩者的計算量相同；根號版本的複雜度較低，當資料範圍變大時，更能發揮優勢。選擇時應先依題目範圍估算計算量，而不是只看這次判題顯示的時間。
