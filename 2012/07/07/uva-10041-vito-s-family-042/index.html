10041 - Vito's Family

題目要求與解法重點

第一行是測試筆數。每筆測資給定親戚人數和各家的門牌，請替 Vito 選一個住址，讓他到所有親戚家的距離總和最小，並輸出這個總和。兩個門牌的距離是兩者相減後的絕對值；多人也可能住在同一個門牌。

選中位數當住址，再加總各家到它的距離，就能得到答案。 最容易理解的實作是先排序、再取中間的門牌；只需要找中位數時，也能用 nth_element 省去完整排序。剛開始學迴圈，則可以先逐一嘗試親戚家的門牌。

為什麼選中位數？奇偶數需要分開處理嗎？

中位數能讓絕對距離總和最小；本題不需要為偶數人數另外計算平均。 把門牌想成由小到大排列，將最左與最右的親戚配成一對：只要住址在兩者之間，到這一對的距離總和就相同。由外向內配對，選中間位置就能同時落在每對的區間內；奇數人時，還能讓正中間那位親戚的距離為零。這是中位數使絕對距離總和最小的性質。

以從 0 開始的索引 r / 2 取值，兩種人數都適用：

  • 奇數人，例如 2、4、6：取索引 1 的 4，距離總和為 2 + 0 + 2 = 4。
  • 偶數人，例如 2、4、6、8：取索引 2 的 6。其實選 4 到 6 之間任一位置，距離總和都是 8。

統計學通常將偶數筆資料的中位數定義為兩個中間值的平均；這題只要求距離總和最小，直接選其中一個中間門牌即可。下面的排序版與 nth_element 版都選較大的那一個。

三種做法怎麼選？

三種做法的差別在於如何找到最佳住址；選定住址後，都只要加總絕對距離。

做法 如何找住址 時間複雜度
暴力法 每個候選住址都算一次總距離，再取最小值 O(r²)
排序法 全部排序後取中位數 O(r log r)
選擇法 用 nth_element 找中位數 平均 O(r)

初學可先寫暴力法；理解中位數後，排序法最直觀；熟悉標準函式後，可用 nth_element 減少計算。 本題範圍小，三種做法都能通過，下面各附一份完整程式。

解法一：暴力枚舉候選住址

把每位親戚的門牌輪流當作候選住址，計算到所有親戚家的距離總和，再取最小值。外層迴圈選住址，內層迴圈累加距離。

只試親戚家的門牌就夠，因為奇數人時的中位數、偶數人時的兩個中間門牌，都在這些候選之中，一定不會漏掉最佳解。

若有 r 位親戚，共有 r 個候選，每個候選計算 r 次距離，時間為 O(r²)。題目的 r < 500，距離計算最多為 499 × 499 = 249001 次。

C++11 程式：暴力法

這份暴力法程式以 C++11 提交至 UVa，獲得 Accepted（submission 31357185，20 ms）。

解法二：排序後取中位數

既然知道中位數就是最佳住址，就不必逐一嘗試候選。先用 std::sort 把門牌由小到大排序，取出 streetNumbers[streetNumbers.size() / 2]，再掃一次加總距離。

例如輸入門牌為 6、2、4，排序後是 2、4、6，選 4，距離總和為 4。

排序需要 O(r log r)，加總需要 O(r)，總時間為 O(r log r)。

C++11 程式：排序法

這份排序法程式以 C++11 提交至 UVa，獲得 Accepted（submission 31362863，0 ms）。

解法三：用 nth_element 找中位數

只需要中位數，不必知道其餘門牌的完整順序，因此可以改用 std::nth_element。 它會把指定位置放上「假如全部排好序，該位置應有的值」，但左右兩側各自不保證有序。

指定 streetNumbers.begin() + streetNumbers.size() / 2，呼叫後該位置就是前面要找的中間門牌。取出它的值，再加總各家到它的距離即可；加總不依賴陣列順序。

一般版本的 nth_element 平均需要 O(r) 時間，加上一次 O(r) 的距離加總，整體平均時間為 O(r)，不保證最壞情況也是線性時間。若需要全部門牌依序排列，仍應使用 sort。可參考 C++ 標準草案：nth_element。

C++11 程式：選擇法

這份 nth_element 程式以 C++11 提交至 UVa，獲得 Accepted（submission 31364264，0 ms）。

資料範圍與空間需求

題目中每個門牌小於 30000、親戚少於 500，距離總和小於 15000000，使用 32 位元 int 足以保存。三份程式都用 vector 保存 r 個門牌，整體空間需求為 O(r)。
